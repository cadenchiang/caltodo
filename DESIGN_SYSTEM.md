# CalTodo Design System

A grounded reference for the **actual** design tokens, patterns, and component recipes in this
codebase (Next.js 16 App Router + Tailwind CSS v4). Every value below is traced to a real file;
citations are `path:line`. When code and this doc disagree, the code wins — fix the doc.

> Sibling docs: [`CLAUDE.md`](./CLAUDE.md) (conventions) and [`UI_STYLE_GUIDE.md`](./UI_STYLE_GUIDE.md)
> (hand-written pattern guide). This file extends both with the concrete token values.

## How to use this doc

1. **Never hardcode a color** for themed UI. Use the CSS-variable-backed Tailwind utilities
   (`bg-card`, `text-foreground`, `border-border`, …) so every one of the 13 color themes + dark
   mode adapts automatically.
2. Copy the **component recipes** verbatim; they are the canonical className strings pulled from
   shipped components.
3. Before adding a component, run the [checklist](#adding-a-new-component) at the bottom.

utility `text-foreground`, `--card` becomes `bg-card`, etc.

(`globals.css:9-20`) declares a fully brand-tinted ramp; the later `@theme inline`
(`globals.css:274-284`) redefines `blue-500 = #0e89d6` but resets the rest toward stock Tailwind
(`blue-600 #2563eb`, `blue-700 #0e89d6`, `blue-100 #dbeafe`, `blue-200 #bfdbfe`…). The `inline` block
is the effective one for `blue-50…950`.

`.force-light` (`globals.css:1658-1673`) hard-pins all tokens to their light values (used on
always-white marketing/auth pages regardless of the user's dark preference).

## Color themes

Dark mode is **class-based** (`.dark` on `<html>`, toggled by a pre-paint inline script in
`layout.tsx:103-158`; supports `light`/`dark`/`auto` where auto uses NOAA sunrise/sunset math).
The `@custom-variant dark` (`globals.css:4`) drives `dark:` utilities.

### Scale & weights (from `UI_STYLE_GUIDE.md` + shipped usage)

| Element | Classes |
|---|---|
| Page title | `text-base font-semibold text-foreground` |
| Modal title | `text-base`/`text-xl font-semibold`/`font-bold text-foreground` (`TaskPickerModal.tsx:78`) |
| Section header | `text-sm font-medium text-foreground` |
| Section label (cards/pickers) | `text-xs font-medium text-foreground` |
| Body | `text-sm text-foreground` |
| Caption / secondary | `text-xs text-muted-foreground` |
| Tiny label | `text-[10px] text-muted-foreground` |

**When to use serif:** reserve `font-serif` (Instrument Serif) for editorial/marketing display
moments and opt-in board titles — never for functional UI chrome, labels, or data.

> Labeling rule (enforced): **no gray all-caps labels.** Do not use
> `uppercase tracking-wider text-muted-foreground` for section headers — use
> `text-xs font-medium text-foreground` (normal case). See known violations in
> [Inconsistencies](#known-inconsistencies).

## Spacing & layout

- **App shell:** flex column `h-dvh`; desktop sidebar + `<main>` row (`src/app/app/layout.tsx`).
- **Main content padding:** `px-4 md:px-10` with `pt-[max(1rem,env(safe-area-inset-top))]`
  (`md:pt-[max(2.5rem,…)]`) — `src/app/app/layout.tsx`.
- **Desktop sidebar:** `w-52`, `px-3 pb-4`, `glass-strong`, `shadow-lg` (`Sidebar.tsx:117`).
- **Grid gutters (style guide):** `px-6 md:px-10`.
- **Content max-widths** (observed frequency): `max-w-md` (28rem, standard modals) and `max-w-sm`
  (compact) dominate; `max-w-2xl`, `max-w-5xl`, `max-w-4xl` for wide page content.
- **Common spacing:** modal/card padding `p-4` (or `px-5 py-4`, `px-6 py-4`); section gaps
  `space-y-4`/`space-y-5`; button gaps `gap-2`; inline icon gap `gap-1.5`.
- **Safe areas:** `body` adds `padding-bottom: env(safe-area-inset-bottom)` (`globals.css:1000`);
  `html` sets `overscroll-behavior-y: none` + `scroll-behavior: smooth` (`991-992`).

### Z-index conventions (observed, `grep`)

`z-10`/`z-20`/`z-30`/`z-40` for local stacking; **`z-50`** is the standard modal/overlay layer
(most common); **`z-[200]`** toasts (`ToastContext.tsx`); **`z-[9999]`** for top-most tooltips/tours;
`z-[10000]`+ reserved for the guided-tour pulse (`globals.css:1913`). Keep new overlays at `z-50`
unless they must sit above another `z-50` surface.

## Radii & elevation

**Radii convention:** `rounded-xl` (12px) for **buttons/inputs/nav items**; `rounded-2xl` (16px) for
**cards/modals** (20 `bg-card` surfaces use `rounded-2xl` vs 5 `rounded-xl`); `rounded-full` for
pills/badges/icon-buttons; `rounded-[4px]` for task checkboxes (`TaskCheckbox.tsx`);
`rounded-lg`/`rounded-md` for small inner controls. Board widget cards use `border-radius: 24px`
(`globals.css:2525`).

**Elevation:**

- Glass layers (`globals.css:1040-1080`): `.glass` `blur(20px)` + `rgba(255,255,255,.55)` (dark
  `.75`); `.glass-subtle` `blur(12px)`; `.glass-strong` reads `--sidebar-bg` (solid, no blur);
  `.glass-dark` `blur(16px)`.
- `.btn-elevated` family (`globals.css:1574-1636`): layered soft shadows with press-in `:active`
  (`scale(.98)` + inset). **Dark mode zeroes the shadow** (`box-shadow: none`) to avoid double-border
  artifacts — this is a hard rule.
- Board widget card (`globals.css:2524-2542`): multi-layer floating shadow + 1px `color-mix` border;
  dark variant is a heavier shadow. Gallery hover (`2117-2130`) lifts `translateY(-2px)`.
- Modals use `shadow-2xl`; toasts/banners `shadow-lg`.

Custom scrollbars are thin (6px), theme-tinted, `rgba(0,0,0,.15)` light / `rgba(255,255,255,.2)` dark
(`globals.css:1004-1038`). `.scrollbar-none` hides them (`2337-2338`).

## Iconography

- **Library:** `lucide-react`.
- **Sizes** (by usage frequency): `14` (most common, compact) › `16` (default inline) › `12`
  (tiny) › `20` › `18`. Larger `24`/`28` for feature/empty states. Match the style guide: `16`
  default, `14` compact.
- **strokeWidth:** lucide's default (2) is used implicitly most places; explicit values seen are
  `2`, `2.5`, `3` (emphasis, e.g. checkmarks), and `1.8`/`2.25` for fine-tuned marks. Prefer the
  default unless matching a specific weight.
- **Color:** `text-muted-foreground` (default), `text-foreground` for emphasis.
- **Accessibility:** icon-only buttons **must** have `aria-label` (e.g. modal close
  `aria-label="Close"`).

## Component recipes

Copy these verbatim. Each is traced to a shipped file.

### Primary button (brand blue)
```
px-4 py-2 text-sm rounded-xl bg-blue-500 text-white hover:bg-blue-600 transition-colors
```
Do: use for the main affirmative action; `bg-blue-500` auto-themes. Don't: hardcode `bg-[#0e89d6]`
outside landing pages. `UI_STYLE_GUIDE.md`; 40 files use `bg-blue-500`.

### Primary button (inverted / high-contrast)
```
px-8 py-3 text-sm font-semibold rounded-xl bg-foreground text-background hover:opacity-90 transition-opacity shadow-sm
```
Do: use for a single dominant CTA (Pomodoro start, modal confirm). Don't: use `bg-foreground
text-background` when you actually want an *explicit* inverted button — the style guide prefers
`bg-gray-900 text-white dark:bg-white dark:text-gray-900` for that. Source `PomodoroPage.tsx:263`,
`TaskPickerModal.tsx:166`.


### Card
```
bg-card rounded-2xl border border-border
```
Padding `p-4` or `px-6 py-4`. Board widget cards use the `.board-widget-card` class
(`globals.css:2529`), which matches this recipe exactly: 16px radius, `--border`, and a subtle
single-layer elevation — so the Home board shares the same surface language as the rest of the app
(previously it was 24px + a heavy 4-layer floating shadow, which read as inconsistent).

### Modal (canonical)
```tsx
<div className="fixed inset-0 z-50 flex items-center justify-center">
  <div className="absolute inset-0 bg-black/50 backdrop-blur-sm animate-announce-backdrop-in" onClick={onClose} />
  <div className="relative bg-popover rounded-2xl shadow-2xl border border-border w-full max-w-md mx-4 animate-announce-card-in overflow-hidden">
    <div className="flex items-center justify-between p-4 border-b border-border">
      <h2 className="text-base font-semibold text-foreground">Title</h2>
      <button aria-label="Close" className="w-8 h-8 rounded-full flex items-center justify-center text-muted-foreground hover:text-foreground hover:bg-muted transition-colors"><X size={16} /></button>
    </div>
    <div className="p-4 space-y-4">…</div>
    <div className="flex justify-end gap-2 p-4 border-t border-border">…</div>
  </div>
</div>
```
Do: `bg-popover` (solid), `backdrop-blur-sm`, portal to `document.body` via `createPortal`, close on
backdrop click, entry animations, `max-h-[85vh] overflow-y-auto` for long content. Don't: transparent
/glass modal backgrounds. Source `UI_STYLE_GUIDE.md`, `TaskPickerModal.tsx:70-75`,
`ContactModal.tsx:114-119`. Note: `ContactModal` uses `bg-card` (also solid) — both are acceptable
solid surfaces; prefer `bg-popover` for dropdowns/pickers.

### Popover / dropdown
Use **`bg-popover`** (solid), `border border-border`, `rounded-xl`, `shadow-lg`/`shadow-2xl`, and
`animate-popover-in`. Never transparent.

### Toast
```
pointer-events-auto relative flex items-center gap-3 rounded-full px-5 py-3 text-sm text-white shadow-lg backdrop-blur-md {bg} overflow-hidden max-w-[calc(100vw-2rem)] animate-toast-in
  bg (default): bg-neutral-800/90 dark:bg-neutral-900/90
```

## Accessibility notes

- **Focus:** inputs use `focus:outline-none focus:ring-2 focus:ring-ring` (or
  `focus:ring-blue-500/30 focus:border-blue-500`). Keep a visible ring — don't remove outline without
  a ring replacement.
- **Icon buttons** require `aria-label` (e.g. `aria-label="Close"`, `"Dismiss"`).
- **Toasts** use `role="status" aria-live="polite"` (`Toast.tsx`).
- **Dark-mode shadow rule:** elevated buttons set `box-shadow: none` in `.dark` to avoid
  double-border artifacts (`globals.css:1600-1636`). Follow this for any new elevated control.
- **Autofill:** custom `-webkit-autofill` box-shadow keeps input backgrounds theme-correct in both
  modes (`globals.css:1639-1687`).
- **Reduced motion:** currently honored by only one animation (`calendar-task-drop-in`). New
  attention-grabbing/looping animations should add a `@media (prefers-reduced-motion: reduce)` guard.
- **Theme flash prevention:** dark/theme classes are applied pre-paint via inline script
  (`layout.tsx:103-158`); nav hidden-item flash prevented similarly (`172-194`).

## Adding a new component

Checklist — enforces the rules above (and the `UI_STYLE_GUIDE.md` anti-patterns):

- [ ] **CSS-variable colors only.** Use `bg-card`, `text-foreground`, `border-border`, `bg-popover`,
      `ring-ring`, etc. No `text-gray-*`, `bg-white`, or `bg-[#hex]` for themed elements. Use
      `bg-blue-500`/`text-blue-500` for the accent so it follows the active theme.
- [ ] **No gray all-caps labels.** No `uppercase tracking-wider text-muted-foreground` for section
      headers/labels. Use `text-xs font-medium text-foreground` (normal case). (Sanctioned uppercase:
      the tiny `text-[9px]` "NEW"-style badge only.)
- [ ] **Solid popovers/dropdowns/modals** — `bg-popover` (or `bg-card`), never transparent/glass.
- [ ] **Radii:** `rounded-xl` buttons/inputs/nav, `rounded-2xl` cards/modals, `rounded-full`
      pills/badges/icon-buttons.
- [ ] **Transitions** on every interactive element (`transition-colors`/`transition-all`); use
      `active:scale-[0.97]` sparingly on primary actions.
- [ ] **Modals**: portal to `document.body`, `z-50`, `bg-black/50 backdrop-blur-sm` backdrop,
      `animate-announce-card-in` + `animate-announce-backdrop-in`, close button with `aria-label`,
      close-on-backdrop, `max-h-[85vh] overflow-y-auto` for long content.
- [ ] **Dark mode:** add `box-shadow: none` (dark variant) on any elevated button. Test in `.dark`
      and at least one `theme-*` (Miffy is the harshest — pink accents + polka-dot bg).
- [ ] **Icons:** lucide, size 16 (14 compact), `aria-label` on icon-only buttons.
- [ ] **No `alert()`/`confirm()`** — use an in-app modal/toast.
- [ ] **Motion:** reuse an existing animation utility; guard looping/large motion with
      `prefers-reduced-motion`.
- [ ] Keep files < 300 lines, one clear purpose (`CLAUDE.md`).

## Known inconsistencies

These bypass the token system and are candidates for cleanup (found via grep on `src/`):

1. **Hardcoded grays: ~234 occurrences** of `text-gray-*` / `bg-gray-*` / `border-gray-*` across
   `src/components` + `src/app` — direct violations of the "CSS variables only" rule. `bg-white`
   appears in ~42 component files.
2. **Hardcoded brand hex `bg-[#0e89d6]` / `#3D8FE8`** in landing + onboarding
   (`LandingNav.tsx:245,254`, `Hero.tsx`, `StatsSection.tsx`, `CanvasStep.tsx`, `CalendarDayCell.tsx`,
   `PensieveStep.tsx`, `GradescopeStep.tsx`). Landing is intentionally `bg-white`/`force-light`, but
   these should ideally use `bg-blue-500` so they theme.
3. **Gray all-caps labels** (explicitly banned): `ContactForm.tsx:48,61,74`
   (`text-gray-500 uppercase tracking-wide`), plus `uppercase tracking-wide` in
   `admin/StatCard.tsx:26`, `admin/RetentionTable.tsx:68`, `CalendarDayCell.tsx:249`,
   `onboarding/page.tsx:260`, `weather-displays/DetailedDisplay.tsx:187`.

   animations (`animate-sync-bar`, `animate-clock-blink`, marquee, etc.) ignore it.

6. **Two "primary inverted" idioms coexist:** `bg-foreground text-background` (shipped, 14 files) vs
